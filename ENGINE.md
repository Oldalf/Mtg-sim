# Simulator: engine notes

The shared engine and how the project is run. Each deck keeps its own plan (`decks/<name>/PLAN.md`: rules, results, what is open), the phases and next steps are in `ROADMAP.md`, commands and layout in `README.md`. These notes were in `PLAN.md` until 2026-11-13 (that file now holds the plan for the roadmap step in progress). It used to hold Gale's whole history; that moved to `decks/gale/PLAN.md`.

## Rules for changing the engine

- **Safety net:** after any change run `npm run verify` (it runs everything below for every deck and must end with VERIFY OK; `-- --eco` for power-save mode). What it runs: `npm run sim -- <deck> --regress check` for every deck with a baseline (a deck with `regress` on its `deck` object; `verify` gets the names from `node dist/sim.js --list-decks`). It replays 600 seeds, the log analyses and the tests and must print IDENTICAL. If a change is meant to alter a deck, check that only that deck differs, then `--regress record` for it. A new test also shows up as DIFFERENT: check that only the tests differ, then re-record.
- **Speed-ups** must be IDENTICAL. Behaviour changes must stay within noise on 2,000+ games, or be the intended change.
- **Noise:** about ±2.6 points at 3,000 games for a percentage. A different list order deals different hands, so lists are not paired: the same cards in another order differed by 2.4 points at 4,000 games and under 1 at 16,000. Use 16,000 games for decisions.
- **Pitfalls found the hard way:**
  - A subclass's field initializers run after the base constructor, so a deck's state is set in field initializers, not in a hook the base constructor calls.
  - `pay(..., commit = false)` taps lands and then undoes it (only `tapped` and the pool). Side effects in `tap()` (life loss, sacrifices) leak into every payment check: do them when `pay` commits.
  - A card's X is 0 in the card data. Backslashes get lost in heredocs and JS template strings written through the shell: check regexes after writing them.
  - Card data comes from Scryfall's bulk files (`engine/cards/scryfall.ts`, `npm run cards -- update`, run by hand when new sets are out). Cards a list needs are copied into `data/cards.json` automatically before a run.
  - Tokens: the deck owns a token's stats (`makeToken`, `makeArtifactToken` for Food, Clue and Servo; the Treasure and the Eldrazi Spawn are the engine's, `engine/cards/tokens.ts`), Scryfall only gives it art (`data/token-art.json`, `pickTokenArt`). The log writes a creature token's face (`CardMove.token`) next to its name, so tokens with the same name and other stats stay apart; a marker token is logged as what it stands for (`makeToken(..., { loggedAs })`, Aesi's armies as x999).

## Rules followed

The reference is the Comprehensive Rules (Wizards' rules text; numbers as in the 2026-06-19 edition, and rule numbers shift between editions). The engine follows the rules where they change results, and says here where it does not.

**The turn and its steps.** `GameCore.step` is `upkeep | draw | main1 | combat | main2 | end`; `enterStep(step)` moves to the next one, empties the pool and, with the log on, notes mana that was lost. A deck reads `step`, or fills in `onEnterStep(step)` (Codie's Mana Drain adds its mana at the start of `main1`). Mana made in a step must be spent in that step.

Followed:
- 106.4: the mana pool empties at the end of each step and phase (`enterStep`). There is no mana burn.
- 500–514: the turn's steps, in order (see the exception for combat below).
- 514.1: discard down to seven cards at cleanup (`endTurn`).
- 514.2: "until end of turn" effects end at cleanup (High Tide, Bubbling Muck and Energybending are per-turn flags, reset in `startTurn`).
- 302.6: a creature with summoning sickness can't tap for mana.
- 601.2g–h and 605: mana abilities are activated while paying a cost, and don't use the stack (`pay` taps sources into the pool, then pays from the pool). The greedy order comes first (the best source for what the pool is short of); when it fails but the untapped sources could pay at all, `engine/game/payment-search.ts` tries other sources and colours (bounded, with the same undo). A committed payment leaves `lastPayment`: each source tapped and what it made.
- 111.10a: a Treasure (`engine/cards/tokens.ts`, `TREASURE`) is a source of any colour that is sacrificed for its mana; an Eldrazi Spawn (`ELDRAZI_SPAWN`) the same for {C}. `pay` spends them last: it first tries without them (`isKeepingExpendableManaBack`), and a committed payment that needed them sacrifices the ones it tapped (`sacrifice`, so the log and death triggers see it); a tested payment keeps them. A test that pays for real and restores a snapshot (`ritualCandidates`, `moveRockFirst` in `planner.ts`) runs `withoutExpendableMana`, since a restore can't bring a sacrificed token back. `SearchMana` counts untapped Treasures (`treasures`, `addTreasures`) and spends them last the same way.
- 602.2: a Signet's {1} is a cost of activating it. A filter source (Dimir Signet, Darkwater Catacombs) is fed from the pool, never with the colour it should make; when nothing else pays, another source is tapped to feed it.
- 117: priority, only as far as the pod's answer window goes.
- 508.1d and 701.15 (pod only): a creature that "attacks each combat if able" (its own text, or Thantis's "All creatures...") and a goaded creature attack each combat if able; a goaded one attacks a player who didn't goad it if it can. Goad ends at the goader's next turn (`PodTable.goaders`). A forced creature the deck's combat didn't send attacks just after it (`attackWithForcedCreatures`), as a second attack.
- 603.2 (pod only): when a player casts a spell, each living opponent's "whenever an opponent casts a spell" permanents trigger before any counterspell (`podAnnounceCast` -> `Arena.announceCast` -> `onOpponentCast`; Taurean Mauler, Rhystic Study in `opponent-cast-triggers.ts`). A new cast path in a deck calls `podAnnounceCast(card)`.

**Dungeons and the initiative** (`engine/game/dungeons.ts`, rules 309, 701.49, 725): rooms are data with small effect functions; `ventureIntoDungeon` enters or moves on (the deck picks the dungeon and the path: `chooseDungeon`, `chooseDungeonRoom`). The initiative ventures into Undercity when taken and at its holder's upkeep; combat damage to the holder takes it; a pod keeps one holder.

**Blink** (`engine/game/blink.ts`, rule 400.7): a blinked permanent comes back as a new object through `enter` (its enter triggers again; counters, marks and summoning sickness start anew), a token is gone, and `onLeave` fires. "Until the next end step" returns wait in `cardsReturningAtEndStep`. The blink spells are card facts (`BLINK_SPELLS`); which permanents is the deck's `blinkValue`. Rebound is an engine rule. A blink in answer to an opponent's removal or wipe: a deck overrides `podShield` (removal aimed at one creature) or `podAnswerWipe` (a wipe about to kill creatures; called for every player before they die) and casts the spell with `resolveBlinkSpell(game, spell, { targets })`, which blinks those permanents until the end of that opponent's turn (`inOpponentTurn`). `podShield(permanent, answer)` also gets the removal, so a deck can answer only a destroy effect (Edgar's Yahenni); `podAnswerWipe` returns the creatures that survive.

**Copies and magecraft** (`engine/game/spell-copies.ts`, rule 707.10): `copySpell` resolves a copy of an instant or sorcery (it is not cast: no cast triggers) and makes a token of a nonlegendary permanent spell's copy. Twinning Staff adds one copy each time, counted once before copying. Casting an instant or sorcery draws with Archmage Emeritus and Archmage of Runes and makes a Treasure with Storm-Kiln Artist; a copy triggers the magecraft ones (Emeritus, Storm-Kiln Artist); Veyran makes each trigger once more. "Whenever you cast a spell" effects of a deck's own cards go in its `podAnnounceCast` override (every cast passes there). **Thunderclap Drake** (2026-11-17): `activateThunderclapDrake` pays {2}{U} and sacrifices it; the next instant or sorcery we cast this turn is copied once per commander cast (`commandCasts`, which `castPerm` now fills for every deck). The copies are made as the spell is cast (`copyNextInstantOrSorcery` in `castInstantOrSorcery`, rebound and flashback), after the deck's `castTriggers` (Gale's recast), and resolve before the spell. When to sacrifice it is the deck's choice (Mike: before a big draw spell; Gale: only in a kill line its search found). **Mizzix's Mastery** (2026-11-18): it exiles an instant or sorcery card from our graveyard (the spell's mode names it; overloaded, mode `overload`, every one) and casts a free copy of each (`castCopyWithoutPaying`: a cast, so cast triggers fire; X is 0), then exiles itself (`EXILES_ITSELF`). Each copy is optional: the deck's `wantsToCastCopy`.

**Firebending** (`engine/game/firebending.ts`): an attacker's printed "Firebending N" adds N {R} when the attack is declared, before the deck's `onAttack`, so the deck can cast spells in combat; the pool empties when the second main phase starts. Firebending a card grants for a turn is the deck's.

**No maximum hand size:** `hasNoMaximumHandSize()` (Reliquary Tower; a deck adds its own cards, as Azula does with Thought Vessel). Thought Vessel is not in the engine's default yet: Ardyn and Helga play it and discard to seven (Mike counts it itself).

**Kill lines are played, not declared** (`engine/game/kill-line.ts`). When a deck's kill search finds a line, `checkKill` plays it on a copy of the game, step by step, through the deck's `playKillStep` (Gale: `decks/gale/kill-play.ts`; Codie does its solver's moves again and casts the finisher). Every cost is paid with `pay`, every card moves. The copy becomes the game only when the line wins there, and in a pod only when no one answers the win (`developWin`, `adoptKillLineCopy`). A line that cannot be played is no win: the log gets a `KILL MISS` line and `killMisses` counts it (the search counted something wrong; `--test` fails on any miss over 300 seeds). A line that only wins on average and falls short with the real cards is a `killChanceFails`. Both are in every deck's `--diag`. A run of the same step (a loop) is logged for 3 rounds, then summed up. Planner rollouts don't play lines: they keep the search's answer. A deck without `playsKillLines()` (no search, or Aesi, whose loops already play in the game) is unchanged. A search that knows what it tapped (`engine/game/search-mana.ts`: sources kept untapped until a payment needs them, so High Tide, Muck and untaps count right; it records the taps) can say so in `plannedPayments`: `pay` taps the sources it names first (`sourcesPlannedFor` in `mana-payment.ts`) and an untap effect untaps the lands it names (`landsToUntap` in `common-spells.ts`) (Gale's search records both, so the played line pays as the search did). Gale's opponents are hit by the search's own rules (`KillSearchState`, through `applyOpponentStep`), so a goldfish opponent's creature cards milled stay the expected share, while our own library is the real cards.

Knowingly not followed:
- Goldfish opponents never act, and in a pod they act only in answer windows. There is no full stack and no priority.
- Combat's steps (506–511) are one step, `combat`.
- Instant-speed plays on other players' turns: the deck hooks `opponentUpkeep` and `opponentEndStep` at each other player's turn (a goldfish game plays one upkeep and one end step for each living opponent between our turns, `playGoldfishOpponentsTurns` in `turn.ts`; Meren sacrifices there), the pod's answers, and one window at the end of the turn just before ours for a deck with `opponents_end_step` on (`engine/game/instant-speed.ts`: instants, and sorceries with flash from Wizards of Thay, Leyline of Anticipation, Vedalken Orrery, Borne Upon a Wind, Quicken or Emergence Zone). No kill is looked for in that window. With it on, Leyline of Anticipation starts on the battlefield from the opening hand (Azula plays it without the window, so not yet for her).
- A goldfish opponent's library is a number, not cards.
- Filter lands, Hideaway and Bojuka Bog's exile are not modelled.
- Loops are cut short after their first rounds, as rule 732 (Taking Shortcuts) lets a player do.
- Untap has no step value: nothing happens in it.

## Card rules

The goal (Pontus, 2026-11-25): the engine knows what every card does, the deck only decides (what to cast, which target, what a card is worth). A card's rules are one plain object in `engine/card-rules/<topic>.ts`:

```ts
{
  names: ['Eternal Witness', 'Timeless Witness'], // the cards that share these rules word for word
  onEnter(game) { returnBestCardToHand(game); },   // the deck chooses through game.returnToHandValue
}
```

The hooks (`CardRules` in `card-rules.ts`): `resolve` (an instant or sorcery resolves), `onEnter`, `onDies` (its own death), `onUpkeep` (each of our upkeeps while it is out), `onOpponentUpkeep` (each opponent's upkeep: the default `opponentUpkeep`), `onLeaves` and `onAnotherOfOursLeaves` (leave triggers: the default `onLeave`), `onAnotherOfOursEnters`, `onOurPermanentDies` (any of ours dies: runs for each of our permanents and the dead one), `onOtherPlayersCreatureDies` (a pod only), `onAttacks` (it attacks; it may return creatures that join the attack, Raph & Mikey), `onWeAttack` (we attack while it is out; it may return creatures that join the attack, Undercellar Sweep), `onLandfall`, `landDropsItGives` (extra land drops while it is out; `landDropsFromPermanents` adds them up), `beforeFirstDrawEachTurn` (Scion of Halaster), `onCreatureCardsMilled` (`millOurselves`), `onCardsLeaveOurGraveyard` (once per event: a spell, or `asOneGraveyardEvent`), `onWeCast` (a permanent spell we cast, with the mana spent; `GameCore.castPerm` runs `permanentSpellCastTriggers`), `onEndStep`, `extraTokensWhenWeCreate` and `replacesTokenWeCreate` (Peregrin Took's Food, Academy Manufactor: `GameCore.createTokenGroup` creates tokens as one event, and `createTokens` goes through it), `onWeCreateToken` (Mirkwood Bats, Rosie Cotton), `onWeGainLife` (`GameCore.gainLife`), `onWeSacrifice` and `onWeSacrificeFood` (`GameCore.sacrifice`), `onCreatureCardToOurGraveyard` (`GameCore.toGraveyard`, not for a dying permanent's card) and `onCreatureCardLeavesOurGraveyard` (`GameCore.takeCard`; Syr Konrad), `onLandTappedForMana` (Crypt Ghast), `onOpponentLosesLife`, `onWeLoseLife`, `onCombatDamageToPlayer` (Glissa), `onOurCreatureDealsCombatDamage` (Ohran Frostfang), `onOurCreaturesDealCombatDamage` (one or more of ours, once per combat: Midnight Pathlighter; `creaturesDealtCombatDamageTriggers`), `whenCast` ("when you cast this spell": the Eldrazi; it runs after the spell, after our permanents' `onWeCast`, also for free casts: `GameCore.cascade`, `castFreePermanentFromHand`), `annihilator` (the pod's `Game.strike`), `onOpponentCasts` (Lurking Predators), `onCreaturesAttackUs` (a pod: Thantis), the replacement `asAnotherOfOursEnters` (what another creature enters with, before any trigger: riot), and the static effects `tokenMultiplier`, `counterMultiplier`, `manaMultiplier`, `opponentLifeLossMultiplier`, `costReduction`, `powerAndToughnessBonus` (one number, or `{ power, toughness }`), `givesOurCreaturesKeywords` and `givesOurCreaturesKeywordsFromGraveyard` (Lavaleaper's haste; Anger, Brawn and Wonder in the graveyard; `GameCore.ourCreaturesHave` asks). Every trigger runs as many times as it triggers (`triggerCount`: Roaming Throne, whose type is the deck's `chosenCreatureType`; a colour a card names is `chosenColour`; `onAnotherOfOursEnters` also once more per Panharmonicon and Starfield Vocalist: `triggerCountOnEnter`). The static ones and the mana and life triggers run at every power, cost, mana and life check, so `GameCore.mayHaveStaticEffects` skips them until a card with one could be on our battlefield (put permanents there with `putOntoBattlefield`, also in tests), and `rulesOf` keeps each card's rules on its `CardDef` (under a symbol key). A new kind of moment (a cast trigger, an activated ability) gets a new hook when the first card needs it, run from the place the game already handles that moment. The engine runs them:
- `resolveSpellByRules`: the first thing `GameCore.resolve` asks; then the engine's topic files (sacrifice-draw spells, land search, reanimation, blink...) and last the deck's `resolveOther`.
- `triggersOfOthersOnEnter` then `enterTriggerOfCommonCard`, `triggersOnDeath` then `deathTriggerOfCommonCard`, `upkeepOfCommonCards` and `opponentUpkeepTriggers` (both then clear `hasCreatureEnteredSinceLastUpkeep`, Ephara's), `leaveTriggers`, `attackTriggers` (or `attackTriggerOf` and `weAttackTriggers` apart), `landfallTriggers` (or `landfallTriggerOf` for one permanent), `upkeepOfCommonCards` and `endStepTriggers` (both take the cards a deck runs at its own place: `runsElsewhere`; or `upkeepTriggerOf`, `endStepTriggerOf`), `ourPermanentDiesTriggerOf` (one permanent's, for a deck with death cards of its own in the same loop), `tokensWeCreate`, `tokenCreatedTriggers`, `lifeGainTriggers`, `sacrificeTriggers`: the engine's default `onEnter` / `onDies` / `upkeep` / `onAttack` / `onLandEnter` call them, and a deck that overrides those hooks calls them where it wants them (so a card's rule there runs only for the decks that call it).

**Whose permanents count.** Each player's game has only its own battlefield, so our hooks see our permanents only: an opponent's creature entering or dying never reaches `onAnotherOfOursEnters` or `onOurPermanentDies`, which matches "you control". A card whose text also counts other players' creatures ("whenever another creature dies": Blood Artist, Elenda, Cordial Vampire) needs `onOtherPlayersCreatureDies` for that half; the pod calls it (`GameCore.onOtherPlayersCreatureDies`, through `announceDeath`). A permanent that changes control doesn't enter (`giveControlTo`); when it dies, its controller's game runs the death.

**What a rule doesn't model** is a comment on the card that starts with `CHECK WHEN ANOTHER DECK PLAYS IT:`: a half of the text not done yet, or a choice that suits only the decks playing it now (Lotus Cobra's colour). When a deck is added (the `/add-deck` skill), each card of its list that has engine rules is looked up in `engine/card-rules/` and every such comment is read and fixed if the new deck needs it.

Shared state a rule needs is on `GameCore`: `useOnceEachTurn(name)` for "once each turn", `isSacrificing`, `drainOne` / `drainAllOpponents`, `extraLandDropsThisTurn`, `biggestCreature`, `millOurselves`, `creaturesInGraveyard`, `tutorToGraveyard`, `rollD20`, `opponentHasMoreLands` (Land Tax: an estimate, we don't see their lands), `hasCreatureEnteredSinceLastUpkeep`, `hasNoMaximumHandSizeForTheGame` (Sea Gate Restoration), `hasCreatedTokenThisTurn` (Idol of Oblivion), `foodsSacrificedThisTurn` (Elanor Gardner), the choices `paysToDraw` (Dawn of Hope, Well of Lost Dreams, Mentor of the Meek), `creatureForCounter`, `tokenToSacrificeFor` (Shire Shirriff), `chooseTokenToCreate` (Tireless Provisioner), `wantsLandFor` (Unlucky Cabbage Merchant), `handCardsToDiscardAndRedraw` (Flux), `instantOrSorceryToPutOnTop` (Mystic Sanctuary), `creatureToSacrificeFor` (Disciple of Bolas), `creatureCardForMerenToReturn`, `landToPutFromHand` and `putLandFromHand` (Growth Spiral), `useAdditionalLandDrop` (Explore), `cardsPlayableThisTurnOnly` (Jeska's Will), `dealDamageToEachOpponent` (Syr Konrad; Gale routes it through its kill search's opponents), the goldfish opponents (`goldfishOpponentHandSize`, `opponentsWheelTheirHands` for Windfall, `mostCardsInAnOpponentsHand`, `opponentsTappedLands`, `millEachOpponent`, `stealCreatureCards` with `enterFromAnotherGraveyard`: a 5/5 `STOLEN_CREATURE` stand-in in a goldfish game, the real cards in a pod, where `Game` overrides them through the arena's `cardsOfGraveyard` and `millOpponent`), the pod hooks (`podEdict`, `podSnipe`, `podSnipeUpTo` returning how many it took, `podFightBestCreature`); in `blink.ts`, `bestCreatureToBlink` and `blinkBestCreature` (the deck's `blinkValue` picks). Counters that aren't +1/+1 are `Permanent.otherCounters` (Airbender Ascension's and Firebender Ascension's quest counters, Mindsplice Apparatus's oil counters; unset until a permanent gets one, so a printed permanent stays the same). **Order:** triggers that happen together run in `orderSimultaneousTriggers` order (the controller's choice; default battlefield order). **Copies:** each permanent triggers on its own, and a copy is "another" permanent (a rule compares permanents, never names). A rule never decides for the deck: wherever the card's text lets its controller choose, it asks the game (`cardValue`, `battlefieldValue`, `returnToHandValue`, `chooseTargetOpponent`, `chooseLandToSacrifice`, `libraryCardsToKeep`, `cardToPutInGraveyard`, `tutorTarget` through `doTutor`, `chooseLandToFetch`...). Two rules for the same name throw when the engine loads.

Moving a deck's card here changes every deck whose list plays it and reaches the hook, so a move is IDENTICAL only for a card no other deck plays (or whose other decks never reach the hook). A card that two decks code differently gets one version, with a before / after.

Cards still handled outside `card-rules/` (to move here step by step): the per-card tables (`ANSWERS`, `BLINK_SPELLS`, `SACRIFICE_DRAW_SPELLS`, `LAND_SEARCH`, `REANIMATION_SPELLS`), the if-chains in the other topic files of `engine/game/`, Baleful Strix and the untap-on-enter cards in `GameCore.enter`, Windfall in `Game.resolveOther`, and the decks' own card code.

## How the game class is split

`GameCore` (`engine/game/game-core.ts`) is the class a deck subclasses. It keeps its state (the fields), the constructor, `clone`, the log lines (`say`, `sayEvent`), the hooks a deck fills in, and every method a deck calls on the game (`this.pay(...)`, `game.draw(...)`), under the same names, so no deck changes when code moves. Methods of a few lines stay as they are.

A large method body lives in a topic file as a plain function that takes the game first, as `blink.ts`, `instant-speed.ts` and `land-search.ts` already did. The method stays as one line that calls it (`pay(cost, ...) { return payCost(this, cost, ...); }`); a private helper moves with no method left. Inside a topic file the game's own methods are called on the game (`game.tap(...)`, `game.manaSourceKind(...)`), never as the topic file's function, so a deck's override still runs wherever it ran before. Moving code changes no logic: every deck stays IDENTICAL.

| File | What lives there |
|---|---|
| `mana-payment.ts` | What a mana source makes (`manaSourceKind`), what the pool is short of, which source to tap, tapping (`tap`), paying (`pay`), and the taps and untaps a kill search planned |
| `untap-lands.ts` | Which tapped lands an untap effect untaps (`untapLands`) |
| `land-play.ts` | Whether a land enters tapped (`entersTapped`), which land to play and playing it (`playLand`, Evolving Wilds, bounce lands) |
| `planner.ts` | What to do next: the deck's candidates in order (rituals that help, a rock first), `develop`, and the turn planner with its rollouts |
| `kill-line.ts` | `checkKill` (the kill search at each step of the turn) and playing a found line on a copy |
| `turn.ts` | The mulligan, the start of our turn (`startTurn`, `beginNewTurn`), moving from step to step (`enterStep`), `developWin`, and one turn of ours (`takeTurn`) |
| `casting.ts` | Casting an instant or sorcery (with rebound, and Blue Sun's Zenith going back into the library) or a permanent spell, the cast triggers, flashback, Wishclaw, transmute, cycling |
| `goldfish-combat.ts` | Goldfish combat for creature decks (`creatureCombat`) |

The pod parts of a game (`Game` in `game.ts`) are split the same way: `pod-attacks.ts` is our side of a pod combat (`arenaCombat`, `planAttack`, `pickDefender`, `homeGuard`, the creatures that must attack, `podDefence`), and `pod-answers.ts` our answers (`answerCost`, `podCast`, `podRespond`, the counter abilities, `podShield`, and what an opponent's answer does to our cards). On the table's side, `engine/pod/pod-interaction.ts` keeps the removal after a turn and the attack preference, `pod-win-answers.ts` answers a win and counters spells, `pod-card-effects.ts` has what one player's card does to the others (Stormdrake, goad, edicts, fight, graveyards, -X/-X).

Two other ways were left out. A chain of classes (`GameMana extends GameZones extends ...`) would need every method one layer uses from a later one declared abstract in the earlier one, and all fields would still sit in the first class (a subclass's fields are set after the base constructor runs). Calling functions from the decks (`pay(game, cost)` for `game.pay(cost)`) would change hundreds of lines in every deck and make them harder to read.

Files still over the guide's 800 lines (step 12, U1, 2026-11-25), and why:
- `game-core.ts`, about 1,620 lines (3,095 before step 11): about 200 lines of state (some 80 fields with their comments, the constructor and `clone`); about 300 of hooks with their default bodies (a hook must be on the class so a deck can override it); about 200 of zone changes and 140 of creatures, life and damage, which decks call hundreds of times and are mostly a few lines long (moving them would only add a one-line method each); about 90 of log lines. Casting and the turn's steps moved out in U1.
- `decks/aesi/game.ts` and `decks/mike/game.ts`, about 890 each, and `decks/meren/game.ts`, about 830: each moved a topic to its own file (Aesi `land-drops.ts` and `combat.ts`, Mike `drawing.ts`, Meren `sacrifice.ts` and `end-step.ts`) and its cards that no other deck plays to the engine. What is left are the deck's state, its turn steps, its win and its overrides. Their other card rules are tied to the deck's own overrides: Aesi's and Mike's `onEnter` and `onLandEnter` don't call the engine's, and Aesi's lands go through its own land drops. Moving them would change what those decks run, so it is a change of its own and not a move.

## What the engine provides

- **Cards** (`engine/cards/cards.ts`): data from Scryfall, with facts that hold in any deck (lands, rocks, cost reducers, counters, tutors, draw spells). Unknown lands are read from their text (colours, "enters tapped", `LandInfo.cond` / `pain` / `colourless` / `colourIf`). **Lands play by their real text for every deck** (`Game.entersTapped`): always-tapped lands, snarls (reveal a card of the types from the hand), check lands (control a land of those types, battle lands count), fast lands (two or fewer other lands), slow lands and battle lands (two or more basic lands), Sunken Hollow. Pain lands deal 1 damage only when tapped for a pain colour (a generic cost uses the free {C}, or the free colour of Murmuring Bosk), dealt when a payment is made, not when it is only tested. Tainted Wood makes coloured mana only with a Swamp. A modal double-faced card with a land on its back (Bala Ged Recovery // Bala Ged Sanctuary) has that land read from the back face's text (`mdfcLand`; `MDFC_LAND_BACK` in `card-facts.ts` overrides it for the cards it names); it is played as a land only when there is no other land in hand and fewer than 5 lands out. Not modelled: filter lands (Twilight Mire is played as a dual), Hideaway, Bojuka Bog's exile. Mana kinds: a colour, `A` (either of the deck's colours), `UB` / `GU`-style pairs, `C<n>` (n colourless).
- **Game** (`engine/game/game-core.ts` and its topic files, see "How the game class is split", plus the pod parts in `engine/game/game.ts`): zones, mana and payment, lands, casting, creatures (power / toughness, counters, tokens), enter and death triggers, sacrifice, devotion, life and damage, the turn loop, mulligans, and the turn planner. A deck subclasses `Game` and fills in the hooks listed in the header of `game/game-core.ts` (`candidates`, `cardValue`, `positionValue`, `tutorTarget`, `onEnter`, `onDies`, `upkeep`, `endStep`, `combat`, `onLandEnter`, `resolveOther`, `diag`, ...). Gale is the worked example for a kill-search deck, Meren for combat, Sam & Frodo for tokens, Aesi for loops.
- **Mulligans:** one free mulligan (a new 7), then London. A deck's rule is plain data in `decks/<name>/mulligan.ts` (format and examples: `engine/game/mulligan.ts`): per attempt (the first 7, the free mulligan's 7, 6 cards) a list of "keep if" clauses, each a land range plus needs (a colour source, a card tag, a cheap spell), and a floor of cards that is always kept (5). A deck without a rule keeps 2–5 lands. `--set smart_mulligan=0` plays the old 2–5 rule for comparison. To change a rule: edit the file, compare with `--set smart_mulligan=0` on 8,000+ games, then re-record the baseline. `--hands` shows how opening hands do by land count and contents (the evidence behind the rules and the primers).
- **Planner** (`engine/game/planner.ts`): tries the best few plays on copies of the game and keeps the best (`planner_width`, `planner_rollouts`), with a deck-specific `positionValue`.
- **Searches on a copy of the game** (Codie's solver, Aesi's loops): `copyForSearch()` (quiet: no log, no kill lines of its own) and `copyAtNextTurn()` (the same at the start of our next turn: `beginNewTurn` untaps, empties the pool, gives a new land drop). A deck's own per-turn state that a search reads is reset in its `beginNewTurn` override (Aesi's land drops). Such a search pays with the real `pay`, so it taps what the game would; only a search on a model of its own (Gale's) needs `SearchMana`.
- **Goldfish combat** (`creatureCombat` in `engine/game/goldfish-combat.ts`, agreed for creature decks): flyers connect; opponents block half of the other attackers (rounded down), the biggest; crackback = a full swing with nothing left home costs as much life as it dealt, each untapped creature kept home cuts a third; a fog creature (Spore Frog) removes it; an attack that wins is always taken; otherwise the biggest attack that keeps us above `combat_safety` (10). Decks may override (Sam & Frodo and Aesi attack with flyers or a few creatures only).
- **Tools:** `--rank` (cards seen by turn 4; a deck's interaction is left out via `rankProtect`), `--cut`, `--analyze` (Archidekt logs: `logTrackers`, `logToken`, `logSacOnTap`, `syncFromLog` per deck), `--diag` (a deck's own consistency measures: `Deck.diagMetrics` and `Game.diag()`; `Game.spent` / `spentEnd` track the mana paid for every deck, Aesi and Meren use them for the slow-start measure), `--hands` (raw opening 7s by land count and by a deck's `handFeatures`, with the average mulligan to 6 as the yardstick; the basis of the primers' MULLIGANS sections), `--trace`, `--regress`.
- **Game logs** (`engine/game-log/game-log.ts` and the `game-log-*.ts` files; the plan they were built from is `PLAN.md` at commit `df7eca7`): with `verbose` on, a game logs events (`GameEvent`: a readable line, its kind, the cards in it, every player's life, the counters on the players, and the card moves in Archidekt's simple format). Counters on a player (not a permanent) are `energyCounters` and `experienceCounters` on the `Game` (change them with `gainEnergy`, `payEnergy`, `gainExperience`) and the opponents' `poison`; an event carries them as `playerCounters`, only the ones above 0, and leaves the field out when all are 0 (`setPlayerCounters`), so logs without counters stay as they were. `isEnergybendingActive` is the Energybending spell, not energy. `say(...)` logs a note, `sayEvent(kind, ...)` a line of a known kind, `sayHighlight(...)` a line worth jumping to. In a log line name an opponent with `opponentName(slot)` and print the opponents' life with `describeOpponentLife()`: a pod then shows deck names. Change a zone only through `takeCard`, `putCard`, `moveCard`, `takeTopCardsOfLibrary`, `putCardsOnTopOfLibrary`, `putOntoBattlefield` and `takeFromBattlefield`, with `takeCardIfThere`, `takeCardAt`, `takeAllCards`, `putCards` and `takeFromBattlefieldIfThere` for the less common cases (or `draw`, `discard`, `toGraveyard`, `enter`, `dies`): they record the move for the log at that moment. In a pod, `giveControlTo` moves a permanent to another player's battlefield (Volatile Stormdrake); it keeps its owner (`Permanent.owner`), and `putCard` sends it to its owner's zone when it leaves the battlefield. The log writes it as `opponentsCards`, Archidekt's zone for another player's cards. A change made by hand (`this.hand.push(card)`) is still found by comparing the table between log lines (`game-log/game-log-moves.ts`, which also gives tapped and counters), but `--test` lists it and fails; `logCardMovesSoFar()` between the actions of a turn keeps them under the right line. A goldfish game and a pod game share the format (`GameLog`). `sim` and `pod` runs write every game to `session-logs/` (`game-log/game-log-files.ts`, gzipped JSON lines, about 2 KB per goldfish game and 8 KB per pod game), tag the games worth reading (`game-log/game-log-tags.ts`) and save those as text; `npm run logs` reads them. The board at any point is rebuilt from the moves (`boardAt` in `shared/game-log-board.ts`); a real Archidekt log loads into the same format (`game-log/game-log-archidekt.ts`); a game of a run can be played again from its `run.json` (`game-log/game-log-replay.ts`). The log must only read the game: `--test` plays 50 seeds with the log on and off and compares; it also checks that a game played again gives the same log and that the rebuilt board equals the game's real zones at every turn end.
- **Shared with the app's page** (`shared/`): the plain type files (`game-log-types.ts`, `run-types.ts`, `pod-types.ts`), the log's board (`game-log-board.ts`) and the rules for reading a log's lines (`game-log-lines.ts`: seat order, which lines name their player, where a turn starts). The engine and the page both import them, so they hold no Node code and import nothing from `engine/`: the page builds them with Angular's own stricter type-check. A change in `shared/` counts as an engine change (`npm run verify` checks every deck).
- **What the app's server calls** (`app/server/`, roadmap step 4). The engine knows nothing of the web: no `http`, no HTML, no printing for the server. Keep these working, without `console.log`, when changing them. Runs: `simulate` (runner) and `simulatePod` (pod) with a `RunControl` (`onProgress`, `stopSignal`; the worker loop is `runJobsInWorkers` in `run/worker-pool.ts`), `createGoldfishRunFolder` / `createPodRunFolder` (`game-log/logged-runs.ts`, shared with `cli/log-session.ts`), `finishLoggedRun`, the power-save numbers (`run/power-save.ts`). Reports as data: `buildKillTurnReport`, `buildDiagReport` (`tools/report.ts`), `buildPodReport` (`pod/pod-report.ts`), with the shapes of `app/api-types.ts`. Logs: `listRuns`, `readRunInfo`, `readIndex`, `readGame`, `clearSessionLogs` (`game-log/game-log-files.ts`), `describeGameResult` (`game-log/game-log-run.ts`), `readArchidektLog`. Decks and cards: `DECKS`, `loadDecklist`, the card data, `cards/card-images.ts` (the image store). The worker threads start from the bundle itself, so the server must stay in the `dist/sim.js` bundle (`npm run app` runs `dist/sim.js app`).
- **Power-save mode** (`--eco`, `--duty N`, `-w N`): `setDuty` in the runner makes each worker rest after a chunk so it is busy only that share of the time; `cli/eco.ts` sets below-normal priority and a quarter of the cores. The seeds don't depend on the worker count, so results are identical (checked with `--regress check --eco`). Use it for long runs while Pontus plays.
- **Speed:** 3,000 games take about 11 s (Meren), 25 s (Aesi), 45 s (Gale) and 50 s (Sam & Frodo, big token boards).
